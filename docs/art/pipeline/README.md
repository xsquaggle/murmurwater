# Asset pipeline scripts

The scripts that turn generated meshes into the GLBs in `public/models/`. They are kept here for reproducibility and are not part of the game build.

Setup, in any scratch folder: create `tools/`, copy these files into it, then
`npm i @gltf-transform/core @gltf-transform/extensions @gltf-transform/functions meshoptimizer sharp three gl-matrix playwright gltf-validator`.

| Script | What it does |
|---|---|
| `splitsheet.py` | Cuts a character turnaround sheet into four square views (front, facing-left, back, facing-right) at one shared scale, for multi-view image-to-3D. |
| `optimize.mjs` | Static meshes: weld, simplify to a triangle budget, drop normal/ORM maps, bake orientation, scale and origin into the vertices (`--fit w,h,d` for a mild non-uniform fit, `--oy` for an origin above the base such as a waterline, `--cut y --legs d` to lengthen legs below a height), build an emissive map, compress textures to WebP. |
| `measure-prop.mjs` | Prints, height by height, a model's radius, extent and upward-facing area: finds a deck, a lid or a waterline before sizing. |
| `open-chest.mjs` | Opens a closed one-piece chest: cuts the mesh at the lid seam, swings the lid back about the rear edge, and builds the rim, the inside and the lid's underside, shaded with vertex colours on a flat patch of the same texture. `node open-chest.mjs chest.glb chest-open.glb --seam 0.31 --angle 105`. It warns if the old shell would show inside (use a larger `--wall`). |
| `build-sail-rig.mjs` | Builds `boats/sail-rig.glb` in code from the painted side elevation of the rig, which gives the proportions and is the texture: lathe mast, tube spars, two-sided sail grid with two morph targets, `belly` (the sail fills) and `furl` (the yard comes down onto the boom with the cloth rolled between them). `node build-sail-rig.mjs sail-rig.png out.glb`. To see a morph: `node render.mjs out.glb sheet.png morph=0,1` (one weight per target). |
| `kit.mjs` | The mesh kit for props that are built in code: parts made of lathes, boxes, tubes and rings, with texture coordinates given in pixels of the atlas (`pack` lays the atlas out and `emit` writes the layout, the UV outlines and the model); named nodes with their own pivots, empties, more than one material. It welds, gives normals up to a crease angle and writes one GLB with a WebP texture. `glow: true` on a material gives it an emissive texture: the model's glow map (`<texture>.glow.png`, written by the painter for patches that name a `glow`) if there is one, else the atlas itself. `strip` places a rectangle by hand (a moss or reed strip that must span the whole height of the texture) and `pack(..., at)` packs the rest beside it. An empty can be turned about Y (`empty(name, at, parent, yaw)`: a socket that says which way to face), and a node's mesh can have morph targets (`Model.morphs(node, names, weights)`; a corner carries where it goes at each target, or a part gives one function for all its corners), with normals worked out again at every target. |
| `paintkit.py` | The painter's half of the kit (numpy, scipy, Pillow): seeded layered noise that can repeat round a lathe, brush strokes, chipped paint with lit and shaded edges, speckles, and an `Atlas` that pastes each patch into its rectangle of the layout and bleeds its border. |
| `mats.py`, `paint-atlas.py` | Painted materials for code-built props (iron, brass, verdigris copper, tin, wood in planks, cork, rope, lamp glass, glowing things, striped cloth; bark, a crown's pad of leaves, hanging moss, reed blades, bulrushes, lily pads, buds; reed thatch, a tide staff, a measuring board, specimen jars, a graduated circle) and what happens to a patch afterwards (painted bevels, shade toward an edge, a waterline with algae, scum and barnacles). A builder names a material for each rectangle of its atlas; `paint-atlas.py layout.json out.png` paints them all. A prop that needs something painted by hand has its own `paint-<name>.py`, which calls `mats.paint_spec()` first. |
| `make-prop.sh <name>` | The three steps for a code-built prop (layout, paint, model), a check that the build repeats byte for byte, and a contact sheet. Run it from the folder that holds the scripts; `PY` names the Python that has numpy, scipy and Pillow. |
| `fen-parts.mjs` | Pieces shared by the Mossglass Fen props: the six-sided caged lantern (base, glass, bars, band, roof, ring or finial), a round window with a frame and glazing bars, and the atlas rectangles they need. |
| `build-fog-lamp.mjs`, `build-sea-road-light.mjs` | `props/fog-lamp.glb` and `props/sea-road-light.glb`: geometry and atlas layout; painted by `paint-atlas.py`. |
| `lantern-tree.mjs` + `build-lantern-tree-a.mjs`, `build-lantern-tree-b.mjs` | The lantern trees of Mossglass Fen from one description each (trunk rings, pads of leaves, bare boughs, roots, knees, how much moss): `props/lantern-tree-a.glb` and `props/lantern-tree-b.glb`. The moss is the material `Glow` with a glow map of its own. |
| `reeds.mjs` + `build-reeds-a.mjs`, `build-reeds-b.mjs` | Clumps of reed blades and bulrushes, `props/reeds-a.glb` and `props/reeds-b.glb`; UV v runs 0 at the foot to 1 at the tip of every blade. |
| `build-lily-glow.mjs` | `props/lily-glow.glb`: six lily pads and two buds (`Glow`). |
| `build-stilt-hut.mjs`, `build-field-kit.mjs`, `build-listening-post.mjs` | `props/stilt-hut.glb` (child node `Vane`), `props/field-kit.glb` and `props/listening-post.glb` (child node `LogBox`): geometry and atlas layout; painted by `paint-atlas.py`. |
| `build-packet-box.mjs` + `paint-packet-box.py` | `props/packet-box.glb` (child node `Pennant`). The painter fills the atlas from `mats.py` and then stencils "M.T." and a fish on the front, the letters drawn as polygons. |
| `fish.mjs` | Fish built in code: a body lofted through sections from the lips to the root of the tail (an open mouth if asked for), eyes as domes on the skin, fins along the back and belly, a tail fan and paired fins as thin two-faced wedges; the right side is built and mirrored, and the fish is fitted to 1 m with its middle at the origin. |
| `build-fen-fish.mjs <fish>` | The ten fish of Mossglass Fen (`fish/reedling.glb` to `fish/the-listener.glb`): shapes, fins, colours and what each carries (whiskers, a sprig of sedge, moss and flowers, stilts, horns). |
| `fishmats.py` | Painted materials for the fish, added to the table in `mats.py`: a skin (colours, bars, bark, scales, a backbone seen through it, a belly lantern, pores, gill and mouth lines), its glow map, fins, eyes, the inside of a mouth, moss, a flower, a blade of sedge. |
| `make-fish.sh <fish>` | As `make-prop.sh`, for one of the fish in `build-fen-fish.mjs`. |
| `figure.mjs` | People built in code: frames and rings of points, skins lofted over them (`loft`, `limb`), lumps for hair, ribbons that lie on a surface (straps, tapes, cords), slabs with rounded faces (pockets, a satchel), and the binds that tie each part to a skeleton's joints (`ladder` by height, `chain` along a limb, `rigid` for a thing that moves in one piece, `mixW`). `kit.mjs` writes the skin: `Model.skeleton(rig)` and a `bind` on every part give `JOINTS_0`, `WEIGHTS_0` (the four heaviest joints) and the inverse bind matrices. |
| `build-calloway.mjs` + `callomats.py` | `characters/calloway.glb` before her clips: Dr. Calloway's shape, the layout of her atlas and how each part is bound; `callomats.py` holds her painted materials (face, skin, hair, straw, waxed cloth, leather, check, dots, tape) and is added to the table in `mats.py`. `--only head,body,limbs` builds some of her, `--norig` leaves the skeleton out. |
| `dump-skeleton.mjs`, `biped-rig.json` | `dump-skeleton.mjs rigged.glb out.json [joints]` writes a rigged character's skeleton as data; `biped-rig.json` is the player's (24 joints: names, parents, rest places, inverse bind matrices), which the builder above stands her in. |
| `borrow-clips.mjs` | `borrow-clips.mjs figure.glb out.glb name=source.glb#clip[:trim=a-b][:hips=k] ...` gives a rigged figure clips from other characters' files, carried over through the skinning matrices, so rest rotations and proportions may differ as long as the joints have the same names. |
| `author-anim.mjs` + `calloway-clips.mjs` | Dr. Calloway's `idle`, `talk` and `wave`: head, spine and arms authored over the sway of the player's idle (`--fingers 0`, no sockets). |
| `make-calloway.sh` | Her whole chain: layout, paint, skinned figure, the player's idle carried over, her clips baked on it, the whole run twice and compared byte for byte, and a sheet. `PLAYER=<player.glb>` says where the player's model is. |
| `make-hollis-rig.mjs`, `hollis-rig.json` | Mister Hollis's skeleton, made from the biped's: `make-hollis-rig.mjs [biped-rig.json] [hollis-rig.json]` moves the 24 joints to his proportions (names, order and rest rotations kept) and adds two joints for each mitten and the joints `Bag` and `Watch` for the things he carries. |
| `build-hollis.mjs` + `hollismats.py` | `characters/hollis.glb` before his clips: his shape, the layout of his atlas, how each part is bound, and the three materials `main`, `Fog` and `Glass`; `hollismats.py` holds what was painted for him (`oilskin`, `knit`, `carpet`, `watchface`, `label`) and is added to the table in `mats.py`. `--only head,body,limbs,things` builds some of him, `--norig` leaves the skeleton out. |
| `author-anim.mjs` + `hollis-clips.mjs` | His `idle`, `talk`, `wave`, `sit` and `pull` and the node `LineHand`. For him `author-anim.mjs` learned two things: joints beyond the biped's keep their rest relation to their parent unless a pose places them (`spec.extra = { Bag: { pos, rot } }`, either a value or a function of the solved pose, so that a thing can follow a hand), and the clips module names in `moving` the joints that get a translation channel. It also measures the hands on the primitive that holds them, since a figure may have others (`HANDS=1` prints what it measured). |
| `make-hollis.sh` | His whole chain: skeleton, layout, paint, skinned figure, the player's idle carried over, his clips baked on it, the whole run twice and compared byte for byte, and a sheet. `PLAYER=<player.glb>` says where the player's model is; `STATIC=1` stops at the figure at rest. |
| `hollis-sheets.sh`, `make-linemark.mjs`, `node-path.mjs` | `hollis-sheets.sh` renders his four contact sheets; aboard he is shown on the Puffin at `Crew2` with a marker from `make-linemark.mjs` hung on `LineHand` (a white line for the line, a red slab for the catch). `node-path.mjs model.glb node clip [steps]` prints where a node is in the model's space through a clip, and which way its +Y and +Z point: how the numbers of `LineHand` were read. |
| `lineup.sh`, `glbinfo.mjs` | `lineup.sh out.png view model.glb ...` renders several characters side by side at one scale (`CLIP=idle TIME=0.3` for a moment of a clip); `glbinfo.mjs file.glb` prints nodes, skin joints, clips, meshes and materials of a GLB. |
| `puffin.mjs` | The sloop Puffin's hull as data and pieces, shared by the boat afloat and her wreck: a table of lines (half breadth, sheer, depth of body and fullness along her), sections as superellipses, and on them the shell in four bands (bottom, boot-top, topsides, sheer strake), keel and stem, transom, rail, rubbing strake, ceiling, cockpit with benches, deck, cuddy, and the lid `HullMask`. |
| `build-puffin.mjs` | `boats/puffin.glb`: her fittings (rudder and tiller on the node `Tiller`, name board, badge, lantern post, tabernacle, cleats, anchor and the rest), the 2048 px atlas layout and the empties the game reads (`Helm`, `Stand`, `MastStep`, `BowStem`, `Lantern`, `Crew1`, `Crew2`). `--sockets file.json` writes their places. |
| `build-puffin-rig.mjs` | `boats/puffin-rig.glb`: mast, shrouds and forestay that stand, and the nodes `Main` (boom, gaff, mainsail) and `Jib`, each with the morph targets `belly` and `furl`. It takes the mast step, the chainplates and the stem from `puffin.mjs`, so the rig lands on the hull. `--sockets file.json` writes its numbers. |
| `build-puffin-wreck.mjs` | `props/puffin-wreck.glb` (`make-prop.sh puffin-wreck`): the same hull from `puffin.mjs`, built upright and then laid over 20° to starboard and lifted onto the bar, with the broken mast, the sprung plank, reeds, weed and the moorhen's nest. Hull pieces are built in the hull's coordinates and moved afterwards, because `mirrored()` mirrors after a part's own transform; what grows or hangs plumb is built in the wreck's coordinates. |
| `boatmats.py` | Painted materials for boats, added to the table in `mats.py`: lapped planking in a colour, bottom paint, a hull side in bands by height (bottom, boot-top, topsides, sheer strake), a name board with block capitals drawn as polygons, a badge with a puffin, a porthole, wickerwork, sailcloth (sewn cloths, tabling along the sail's own outline, reef points, a patch); and for the wreck `aged` (paints any other material named in `of` and then weathers it: fading, algae in the low places, lichen and droppings on top), `nest` (wound reed stems) and `egg` (buff with spots). |
| `make-puffin.sh [cell]` | Builds the Puffin's hull and rig, checks that each repeats byte for byte, and renders them together under sail, on the other tack, furled, and the deck from above. It expects the scripts in a folder called `tools`, as `render.mjs` does. |
| `probe-top.mjs` | `probe-top.mjs model.glb x0,x1,nx z0,z1,nz [ymax]` prints the height of the highest surface under a grid of points: how a place to sit was found on the skiff, which is one fused mesh. |
| `regress.sh [repo]`, `validate.mjs` | `regress.sh` rebuilds every code-built prop, the Fen fish, the Puffin with her rig, her wreck, Dr. Calloway and Mister Hollis and compares each with the file in the repo byte for byte: run it after any change to `kit.mjs`, `mats.py`, `paintkit.py`, `figure.mjs` or `author-anim.mjs`. `validate.mjs model.glb ...` runs the Khronos glTF validator and prints its counts and first messages. |
| `uvcheck.mjs <model.glb>` | For every primitive: the v of its lowest and highest vertices, its v range, whether it is emissive and double-sided; and the size of every texture. The check that blades and moss run 0 at the root to 1 at the tip. |
| `sheet2.mjs <out.webp> <top.png> <bottom.png>` | Stacks two rendered strips (by day and after dark) into one 1536 x 768 sheet. |
| `build-pot-float.mjs` + `paint-pot-float.py` | `props/pot-float.glb`, geometry and texture. `node build-pot-float.mjs out.glb --layout l.json` writes the atlas layout, `python paint-pot-float.py l.json tex.png` paints it, `node build-pot-float.mjs out.glb tex.png` builds the model (`--uv uv.svg` writes the triangle outlines to lay over the texture). |
| `build-belfry.mjs` + `paint-belfry.py` | `props/belfry.glb`, the same three steps as the float (`--layout`, paint, build) with a 2048 px atlas. The builder holds every size (tower, openings, roof, lean, where the roof is open); the bell is its own node with its pivot on the headstock, and `RopeSocket` is an empty under it. `paintkit.py`'s `masonry` lays coursed stone, flags and slates. |
| `merge-anim.mjs` | Characters: merges several single-clip auto-rig outputs of the same mesh into one GLB with named clips. Each auto-rig job returns a different skeleton, so clips are retargeted through the skinning matrices onto the first file's skeleton. Also removes the armature's 0.01 scale so the skeleton is in metres. Per-clip flags: `:inplace` removes root drift, `:anchor` starts the clip over the model origin, `:trim=a-b` keeps part of it. |
| `emissive.mjs` | Shared by the two scripts above: builds the glow map from warm bright texels, optionally limited to a 3D box. |
| `author-anim.mjs` + `wick-clips.mjs` | Wick's sketchbook clips: the same solver without finger joints (`--fingers 0`), arms authored on top of the library idle, look and talk clips, plus the `BookSocket` empty. `node author-anim.mjs wick.glb out.glb wick-clips.mjs --fingers 0`. |
| `author-anim.mjs` + `player-clips.mjs` | Player fishing and boat clips. Adds four finger joints (found from the hand geometry) and the `RodSocket` and `CatchSocket` empties, then bakes clips described as pose specs (hips, spine, look target, hand targets solved with two-bone IK, finger curl) on top of the rest pose or a frame of a library clip. `node author-anim.mjs player.glb out.glb player-clips.mjs --drop cast`. To add one clip later without touching the others: `--only boat_sit`. |
| `skin-pose.mjs`, `anim-diff.mjs` | `skin-pose.mjs model.glb clip time [x range] [joint regex]` skins the mesh at one moment of a clip and prints its underside, joints and sockets (how `boat_sit` was seated on a thwart 0.465 m above the boards). `anim-diff.mjs a.glb b.glb` lists the largest difference per clip between two files (proof that adding a clip changed no other). |
| `rig-cat.mjs` | Biscuit: builds a quadruped skeleton, skin weights (geometric segmentation plus Laplacian diffusion) and procedural walk, idle and sit clips. `node rig-cat.mjs stand in.glb out.glb` (or `sit`). |
| `render.mjs` + `viewer.html` | Renders a turntable contact sheet (or frames of a clip) with three.js in headless Chromium and prints triangle count, bounds and clip list. `dark=1` shows only the emissive parts; `glow=0` turns them off, as the game does by day; `water=1` lays a sheet of water at y = 0 (`waterY=0.2` moves it, for a model whose origin is on the ground); `rod=1` and `fish=1` draw a debug rod and fish on the sockets; `focus=x,y,z,r` fixes the camera target; `add=<url>@x,y,z[,yaw]` places further models in the scene (the rig on the skiff); `morph=<w>` sets every morph weight (`morph=0,1` one per target); `hide=Name,...` hides nodes by name (the Puffin's `HullMask`). |
| `clip-sheet.sh`, `pose-sheet.sh` | Clip strips (one row per clip, six frames) and pose comparisons, built on `render.mjs` and ImageMagick. |

Conventions for every model: glTF, +Y up, metres, front (face, mouth, bow) toward +Z, one material (a prop built in code may have a second, named one where the game needs it, such as `Glass`), base-colour texture in WebP (`EXT_texture_webp`), metallic 0, roughness 0.9, no mesh compression.

## Voice lines (`voice/`)

The scripts that turn generated speech into the files in `public/audio/voice/`. Setup: Python 3 with `torch transformers soundfile numpy scipy faster-whisper speechbrain`, ffmpeg with libmp3lame and libsoxr, and Playwright for the browser check. Raw takes are not kept in the repo; each line's job id is in `takes.json` and `docs/ASSETS.md`.

| File | What it does |
|---|---|
| `takes.json` | One entry per line: the take that was kept, its generation job id, the voice id, the text hash and the exact prompt (delivery direction in square brackets, then the line). |
| `add.py` | `add.py <key>=<result url> ...` downloads a take to `raw/<speaker>__<line>.t<n>.mp3` and notes it in `jobs.json`. |
| `process.py` | Chosen take to finished file: speaker tuning (Pell lower and slower, Wick raised into a child's voice), cut to the speech, limiter, -16 LUFS measured on the encoded MP3, mono 44.1 kHz 128 kbps. `--all-takes` writes every take to `alt/` for comparison. |
| `check.py` + `analyze.py` | The "ears": for every file, perceived age and child probability (wav2vec2 age-gender model), pitch, pace, a transcript compared with the script (faster-whisper `small.en`), silence at both ends, loudness and peak. |
| `second.py` | A second transcript with a larger recogniser (`medium.en`), listing only the lines that differ from the script. |
| `spk.py` | Speaker-embedding similarity of every take to its character's average, to catch takes that drift from the voice. |
| `browser-check.cjs` | Decodes every file listed in `voiced.json` in headless Chromium, the game's runtime, and reports silence at both ends and peaks. |

To redo a line after its text changes: generate it with the same voice id and a direction in the style of `takes.json`, `add.py` the result, set the take in `takes.json`, run `process.py <key>`, run the checks, copy `final/<key>.mp3` to `public/audio/voice/` and put the new hash in `voiced.json`.

## Music and sound effects (`audio/`)

The scripts behind `public/audio/music/` and `public/audio/sfx/`. Setup: Python 3 with `numpy scipy soundfile librosa torch transformers py7zr`, ffmpeg with libvorbis, and Playwright for the browser check. Downloads and raw generations are not kept in the repo. To rerun, copy this folder to `<work>/tools/` and put the sources beside it: `<work>/oga/<pack>/` (written by `oga_page.py --get`), the two Kenney packs unzipped to `<work>/cc0/kenney-interface/` and `<work>/cc0/kenney-rpg/`, generated clips in `<work>/sfx/raw/` and `<work>/music/raw/` (written by `get.py`). Archives inside a pack are unpacked next to themselves into `<name>.x/`.

| File | What it does |
|---|---|
| `generated.json` | Every generated clip: name, job id, model, prompt and length asked for (music and sound effects). |
| `get.py` | `get.py <music|sfx> <name>=<result url> ...` downloads a generation to `<kind>/raw/<name>.mp3` and notes its job id. |
| `oga_search.py`, `oga_page.py` | Search OpenGameArt for CC0 sound effects; print a page's author, licences and files, and with `--get` download them to `oga/<slug>/` with a `SOURCE.json`. |
| `ears.py` | The "ears": AudioSet tags (AST) and CLAP audio-to-text matching for any clip. |
| `survey.py`, `events.py`, `ev.py` | One line per file in a folder (length, peak, tags); the separate sound events inside a clip and their times. |
| `audition.py` | Try a candidate cut or layering before it goes in the manifest: its CLAP rank among the 28 sound descriptions and its tags. |
| `listen_music.py` | Tempo, key, tags and level of a music track, window by window. |
| `loop.py` | Cut a seamless music loop: candidate start and end points on phrase boundaries, crossfade into the audio before the loop start, seam report. |
| `master_music.py` | Loops and stings to -18 LUFS OGG Vorbis, checking that the decoded length is the length written; a sting can be transposed by playing it faster or slower. `master_music.py <name>` does one file. |
| `sfx_manifest.py` | What every sound effect is made from: source file, cut, speed, layers, level. Also the pack list and the synthesised chime. |
| `sfx_fen.py` | The Mossglass Fen sounds, called from the manifest: the Fog Lamp, the sea-road chimes, the crossing, the packet box, the reeds, and the two ambience loops, which are laid round a ring (a bed, and single events placed on it) and not cut from one recording. |
| `fen_judge.py` | For the Fen sounds: tags, CLAP rank, how well a few other descriptions fit, and for a loop the tags and level of every six seconds. |
| `unpack.py` | Unpack a downloaded `.zip` or `.7z` into `<name>.x/`, refusing paths that leave it. |
| `sfx_build.py` | Builds every effect in the manifest: cut, layer, trim to the sound, level, encode, and write `index.json`. Output is byte-identical from run to run. |
| `sfx_check.py`, `sfx-check.json` | CLAP rank and AudioSet tags of every finished effect. |
| `loop_check.py` | Whether a loop's wrap point stands out from the rest of the loop. |
| `browser-check.cjs` | Decodes every music and effect file in headless Chromium and prints channels, sample rate and exact length. |
| `assets_md.py`, `assets_update.py`, `sfx-index.json` | The per-file source tables in `docs/ASSETS.md`, written from the build's index; `assets_update.py docs/ASSETS.md` replaces the three tables in place. |

Two things learned the hard way. Chromium's Vorbis decoder can return a short file up to 128 samples short at the end, so one-shots carry 4 ms of trailing silence and loops are rotated until they decode to exactly their length (a loop sounds the same from any starting point). And generation is hit and miss for mechanical sounds: short caption-like prompts work for common sounds (a cat, coins, water, rowing, creaking wood, steps on grass) and fail for a reel, a whoosh or a plop, which is why those come from CC0 recordings.
